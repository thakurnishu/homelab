## Proxmox host

The machine runs Proxmox VE; Kubernetes nodes and service appliances are guests
on it. Managed over SSH:

| Alias | Target | What |
|---|---|---|
| `proxmox` / `pve` | `192.168.1.110` | Hypervisor node |
| `pihole` | `192.168.1.111` | Pi-hole CT 100 |

```bash
ssh proxmox 'qm list; pct list'      # VMs and containers
ssh pihole  'pihole status'
```

### SSH host inventory

Those aliases are **tracked in this repo** and symlinked into place, so the guest
inventory is versioned alongside the thing that creates the guests:

```
homelab-setup/ssh/config.homelab      <- edit and commit this
  ^ symlinked from ~/.ssh/config.homelab
    ^ pulled in by ~/.ssh/config via `Include ~/.ssh/config.homelab`
```

Set up the symlink on a new machine with:

```bash
ln -s "$PWD/homelab-setup/ssh/config.homelab" ~/.ssh/config.homelab
```

`~/.ssh/config` must include it **before** its `Host *` block — `ssh_config` is
first-match-wins, so a catch-all placed earlier would answer first.

Creating or destroying a guest is expected to update this file; the skills below
treat that as part of the operation rather than an afterthought. Host *keys* stay
out of git — `ssh-keygen -R <ip>` after a destroy is machine-local state.

> Since this repo is public, entries here are public. They are RFC1918 and
> unreachable from the internet. Anything with a routable address or an
> organisation's name belongs in `~/.ssh/config.local`, which stays untracked.

Scripts under `homelab-setup/` use the explicit `ssh -i ~/.ssh/proxmox root@<ip>`
form instead of the aliases, so they run on machines where this isn't set up.

| Guest | Purpose |
|---|---|
| CT `100` `pihole` | Network DNS + ad blocking — see `homelab-setup/pihole/` |
| VM `9000` `ubuntu-24.04-cloud` | Cloud-init template; clone it to make new VMs |

> **Two-node cluster caveat.** The second node is usually powered off, which
> costs quorum and remounts `/etc/pve` read-only — every write then fails with a
> confusing `Permission denied` that never mentions quorum. Fix with
> `ssh proxmox 'pvecm expected 1'` (not persistent across reboots).

Day-to-day VM and container operations are documented as Claude Code skills in
`.claude/skills/proxmox-vm/` and `.claude/skills/proxmox-ct/`.

## Flux Dependency Hierarchy

Resources are applied in a strict order enforced by `dependsOn` across four Kustomization objects defined in `clusters/homelab/`.

```mermaid
graph TD
    Bootstrap[flux bootstrap] --> GitRepo[GitRepository: flux-system\nbranch: main]
    GitRepo --> FluxKS[Kustomization: flux-system\npath: ./clusters]

    FluxKS --> InfraNamespaces[infra-namespaces\npath: ./infrastructure/namespaces]

    InfraNamespaces --> InfraControllers[infra-controllers\npath: ./infrastructure/controllers/enabled]
    InfraNamespaces --> InfraConfigs[infra-configs\npath: ./infrastructure/configs/enabled]

    InfraConfigs --> ProdApps[prod-apps\npath: ./apps/overlays/production]
```

- `infra-namespaces` has no dependencies and runs first.
- `infra-controllers` and `infra-configs` both depend on `infra-namespaces` and reconcile in parallel.
- `prod-apps` waits for `infra-configs` before deploying applications.

## Secret Management

Two layers of secret management work together:

**Hashicorp Vault + External Secrets Operator** — runtime secrets for applications. Apps reference `ExternalSecret` objects that pull live credentials from Vault. The Vault token itself is bootstrapped via SOPS.

**SOPS + Age** — secrets that must be committed to Git (e.g., Vault token, image pull secrets, DB passwords for bootstrap). Encrypted at rest; Flux decrypts in-cluster using the `sops-age` Kubernetes Secret.

## GitOps Workflow

```mermaid
sequenceDiagram
    participant Dev as Developer
    participant GH as GitHub (main)
    participant Flux as FluxCD
    participant Vault as Hashicorp Vault
    participant K8s as Kubernetes

    Dev->>GH: git push
    Flux->>GH: polls every 1m, detects new commit
    Flux->>Flux: decrypts SOPS secrets via sops-age
    Flux->>K8s: applies infra-namespaces
    Flux->>K8s: applies infra-controllers + infra-configs (parallel)
    Flux->>Vault: ExternalSecrets fetch live credentials
    Vault->>K8s: secrets injected into cluster
    Flux->>K8s: applies prod-apps
```
